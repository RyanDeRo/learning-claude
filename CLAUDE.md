# Learning Claude — Personal AI Skill-Building Lab

## Who I am
I'm a PagerDuty implementation consultant. AI is disrupting my field, and I need to become an effective user and operator of AI or risk being replaced. This repo is where I retool.

I'm a beginner across most of these domains (coding, design, business). Explain the *why* behind decisions, not just the *what* — I'd rather understand what's being built than copy-paste code or advice I don't follow.

## Why this repo exists
Two goals, both served by the same practice of building real things with AI:

1. **Job security** — get sharper at using AI so I stay valuable as a PagerDuty consultant (and in whatever consulting/implementation work looks like as AI reshapes it).
2. **Side income** — I don't yet know which lane will pay off, so I'm deliberately sampling several: consulting, app creation, web design, investing, real estate. Each subfolder here is a rep at one of these, not a final bet.

Every project should be justifiable against at least one of these two goals. If a task doesn't build a skill or move toward income, it's probably scope creep.

## How each project is organized
Every real project lives in its own subfolder (e.g. `Local Website Build/`, `Focus Timer - BJJ/`) with its own `CLAUDE.md` for project-specific rules, its own journal, and its own context. This root file sets the overarching philosophy; subfolder files set the specifics. Both apply when working inside a subfolder — read the local one first, but this one still governs tone and priorities.

## How to work with me
- Teach as we go. When you make a technical or business choice, say why, and name the tradeoff you picked over.
- Treat every project as a chance to build a transferable skill (prompting, AI tool usage, folder/context structure, judgment about when AI output is good enough) — not just to ship the artifact.
- Be honest about what's a viable money-making direction and what's just a fun build. I'd rather hear "this is a good learning exercise but a weak business" than have that go unsaid.
- Keep solutions simple enough that I can maintain, explain, and repeat them — sustainability matters more than cleverness.

## Journals
Each project subfolder keeps its own journal (`journal.md`) logging sessions, decisions, and next steps. Update the relevant one after meaningful work in that project.
